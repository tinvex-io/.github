# Contributing to Tinvex

Thanks for your interest in contributing. These guidelines apply to all public Tinvex repositories.

## Reporting bugs and requesting features

Search the existing issues first. If you don't find a match, open a new issue using the template and include as much detail as you can: what you expected, what happened and how to reproduce it. For open-ended questions and ideas, use the organization Discussions.

## Sending changes

Fork the repository and create a branch from main. Keep each pull request small and focused on a single change. Explain what the change does and why, link the related issue, and make sure tests and linters pass before asking for review.

## Commit messages

Write short, descriptive commit messages in the imperative mood, for example: Add season ticket check-in.

## Security

Please do not report vulnerabilities in public issues. Follow our Security Policy instead.

## Code of Conduct

By taking part in this project you agree to follow our Code of Conduct.
